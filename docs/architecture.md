# 구조와 책임

## 사용자 작업에서 출발

도서관 탐색, 문서 생성·수정·이동·삭제, 페이지 편집, 필기 이해, 다른 스킬의 산출물 배치가 관심사다. 특정 문제풀이/답안 작성 흐름에 종속되지 않는다. 기능별 실제 가능 여부는 CLI `capabilities`와 README에 표시한다.

| 계층 | 책임 | 구현 |
|---|---|---|
| Codex 스킬 | 의도 해석, 대상 식별, 다른 스킬 호출, 결과 안내 | `skills/flexcil`, `flexcil-setup` |
| 표준 문서 전달 | PDF와 제목·목적 폴더·출처 전달, 가져오기 매칭 | `handoff.py` |
| 도서관 | Flexcil 가상 폴더, 목록, 휴지통, 경로 배치 계획 | `library.py` |
| 문서 엔진 | 제한이 있는 ZIP/JSON 읽기, 페이지와 객체, 원본 보존 | `codec.py`, `edits.py` |
| 읽기용 시각화 | PDF 배경+필기/텍스트 → PNG, 래스터 PDF | `render.py` |
| 상태·복구 | 계정별 설정, 변경 작업, 사전 검사, 재검증, 복구 후보 | `state.py` |
| 전송 | Google 인증, 실제 다운로드/업로드 | 기존 Codex Google Drive 앱 |

Python 코어는 네트워크를 사용하지 않는다. 전송을 분리했으므로 로컬 `.flx`만으로 포맷과 변형을 시험할 수 있다. 서버·MCP가 없어도 스킬이 CLI와 기존 커넥터를 조합해 작업한다.

## 도메인 식별자

- Drive folder/file ID: 전송 주소.
- Document UUID: `info.key`, 목록의 `document` 참조.
- List-item UUID: 문서나 가상 폴더의 `key`.
- Page UUID: `pages.index[].key`.
- Object UUID: 페이지 안의 필기·텍스트 등 객체 `key`.

제목은 식별자가 아니다. 중복 제목은 경로/UUID로 구별한다. UUID를 Drive file ID로 사용하지 않는다.

## 변경 절차

문서 변경은 **다운로드 → 예상 해시 확인 → 복사본 편집 → 검증 → 원본/후보 보관 → 최신 다운로드와 비교 → 기존 ID에 업로드 → 재다운로드 검증** 순서다. 원본 파일은 로컬 편집 명령이 덮어쓰지 않는다. 알려지지 않은 ZIP 항목은 그대로 보존한다.

도서관+휴지통은 서로 다른 파일이다. Drive API 트랜잭션이 없으므로 순서를 갖는 복구 가능한 작업으로 다룬다. 각 파일의 before/candidate 해시를 기록한다. 중단 후 이미 적용된 단계를 재실행하지 않으며, 외부 변경이 있으면 다시 계획한다.

설치 상태와 사용자 상태는 분리한다. 플러그인 업데이트는 프로필·백업을 덮어쓰지 않는다. 토큰은 Google 연결 계층에 남는다. 특정 사용자나 태블릿의 경로를 코드에 넣지 않는다.

## 새 문서와 완성 기준

기존 문서 갱신과 신규 등록은 다른 기능이다. 실제 Android 실험으로 기존 문서 갱신은 성립한다. 신규 파일은 앱 전용 속성 필터에 포함되어야 하며, 현 커넥터는 그 등록을 수행할 수 없다. 현재 `handoff.py`는 이 차이를 상태로 나타낸다.

`awaiting_native_import → registered_needs_placement → [문서 이름 변경/폴더 배치/재검증] → 완료`

수동 가져오기를 요구하는 상태를 자동 생성 완료라고 표시하지 않는다. 디버깅·앱 설치를 사용자가 원하지 않는 경우 이를 몰래 추가하지 않는다. 완전 자동 신규 생성, 복제, 전체 객체 렌더링/편집, 영구 삭제의 실제 지원은 추가 개발·검증이 필요한 항목이다.
