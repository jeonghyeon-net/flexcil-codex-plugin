# 구조와 책임

## 사용자 작업에서 출발

도서관 탐색, 문서 생성·수정·이동·삭제, 페이지 편집, 필기 이해, 다른 스킬의 산출물 배치가 관심사다. 특정 문제풀이/답안 작성 흐름에 종속되지 않는다. 기능별 실제 가능 여부는 CLI `capabilities`와 README에 표시한다.

| 계층 | 책임 | 구현 |
|---|---|---|
| Codex 스킬 | 의도 해석, 대상 식별, 다른 스킬 호출, 결과 안내 | `skills/flexcil`, `flexcil-setup` |
| 표준 문서 전달 | PDF와 제목·목적 폴더·출처 전달, 가져오기 매칭 | `handoff.py` |
| 신규 문서 | PDF 문서 구성, 문서/목록 ID 발급, 폴더 배치, 생성 작업 기록 | `creation.py` |
| 도서관 | Flexcil 가상 폴더, 목록, 휴지통, 경로 배치 계획 | `library.py` |
| 문서 엔진 | 제한이 있는 ZIP/JSON 읽기, 페이지와 객체, 원본 보존 | `codec.py`, `edits.py` |
| 읽기용 시각화 | PDF 배경+필기/텍스트 → PNG, 래스터 PDF | `render.py` |
| 상태·복구 | 계정별 설정, 변경 작업, 사전 검사, 재검증, 복구 후보 | `state.py` |
| 연결 설정 | 로컬 클라이언트 설정, APK의 공개 설정 읽기, Mac 콜백 수신 | `connection.py`, `oauth_receiver.swift` |
| 전송 | PKCE 인증, 갱신, 속성 조회, 페이지네이션, 이어 올리기 | `direct.py`; 기존 파일은 Codex Google Drive 앱도 사용 가능 |
| 여러 파일 변경 | 문서와 목록의 이름 변경, 휴지통·복원 순서, 중단 후 재개 | `transactions.py` |

포맷·편집 코어는 네트워크를 사용하지 않는다. 연결·전송 모듈을 분리했으므로 로컬 `.flx`만으로 변형을 시험할 수 있다. 스킬이 CLI와 필요한 연결을 선택하며, 별도 서버·MCP는 필요하지 않다.

## 도메인 식별자

- Drive folder/file ID: 전송 주소.
- Document UUID: `info.key`, 목록의 `document` 참조.
- List-item UUID: 문서나 가상 폴더의 `key`.
- Page UUID: `pages.index[].key`.
- Object UUID: 페이지 안의 필기·텍스트 등 객체 `key`.

제목은 식별자가 아니다. 중복 제목은 경로/UUID로 구별한다. UUID를 Drive file ID로 사용하지 않는다.

## 변경 절차

문서 변경은 **다운로드 → 예상 해시 확인 → 복사본 편집 → 검증 → 원본/후보 보관 → 최신 다운로드와 비교 → 기존 ID에 업로드 → 재다운로드 검증** 순서다. 원본 파일은 로컬 편집 명령이 덮어쓰지 않는다. 알려지지 않은 ZIP 항목은 그대로 보존한다.

도서관+휴지통은 서로 다른 파일이다. Drive API 트랜잭션이 없으므로 순서를 갖는 복구 가능한 작업으로 다룬다. 각 파일의 before/candidate 해시를 기록한다. 중단 후 이미 적용된 단계를 재실행하지 않으며, 외부 변경이 있으면 다시 계획한다.

설치 상태와 사용자 상태는 분리한다. 플러그인 업데이트는 프로필·백업을 덮어쓰지 않는다. 직접 연결 토큰은 사용자 상태 디렉터리에 제한된 권한으로 저장한다. 특정 사용자나 태블릿의 경로를 코드에 넣지 않는다.

## 새 문서와 완성 기준

신규 파일은 앱 전용 속성 필터에 포함되어야 한다. `connection-probe`가 해당 OAuth 연결에서 실제 속성을 읽는지 검증한다. 이 조건을 만족한 직접 연결로 신규 문서의 태블릿 표시와 필기 회수까지 확인했다.

`prepared → document_verified → cloud_verified → device_verified`

생성은 Drive ID를 먼저 예약하고 문서를 올린 다음 목록을 갱신한다. 중간 실패 시 같은 ID와 업로드 세션을 사용한다. 원본/후보가 바뀌면 재시도를 중단한다. 앱 표시와 새 필기 회수는 명시적 사용자 확인이 있어야 검증 상태로 기록된다.

직접 연결이 없는 경우 `handoff.py`의 수동 가져오기 상태를 사용할 수 있다. 이를 기본 생성 경로나 자동 완료로 표시하지 않는다. 복제, 전체 객체 렌더링/편집, 영구 삭제는 남은 개발 항목이다.
