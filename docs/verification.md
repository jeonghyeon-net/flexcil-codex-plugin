# 검증 기록

2026-09-28, macOS arm64에서 수행했다. 개인정보가 없는 요약만 저장한다.

## 통과

- Python 3.12.14 새 가상환경에 지정된 의존성 설치 후 `doctor` 실행.
- 합성 자료를 사용하는 자동 테스트 **31개** 통과.
- ZIP 경로 탈출/중복 콘텐츠, 비정상 필기 데이터, 압축 목록 크기·끝 검사.
- 편집 도중 오류가 발생했을 때 입력 불변, 오래된 해시 거절, 출력 파일 덮어쓰기 거절.
- 새 PDF/빈 페이지, 페이지 순서 변경/삭제, 객체 삭제, 문서·폴더 이동/휴지통/복원.
- 표준 PDF 가져오기 작업 명세와 실제 첨부 PDF 해시 매칭, 중첩 폴더 배치 계획.
- 사용자 테스트 전 일반 쓰기 거절, 원격/후보 변경 감지, 장치 왕복 기록에 추가 객체 요구.
- 미리보기와 유효한 PDF 내보내기. 근사 렌더를 `--strict`로 거절.
- 실제 비공개 `.flx` 샘플 **8개**에 텍스트 추가, 재직렬화/재읽기, 기존 필기 의미 보존. 샘플은 저장소에 넣지 않았다.
- 네이티브 ZIP에서 발견된 중복 `.itemInfo` 바이트 보존.
- 공식 `validate_plugin.py`, 두 스킬의 `quick_validate.py` 통과.
- Codex CLI를 통한 로컬 marketplace 등록 및 플러그인 설치. 설치 캐시에서 `capabilities` 실행 확인.

## 실제 Android/Drive 실험

1. 사용자가 별도 테스트 노트를 생성했다.
2. 원본 바이트를 보관하고 UTF-8 텍스트 객체 하나를 넣었다.
3. 직전 원격 파일과 원본이 일치함을 확인한 뒤 같은 Drive ID에 업로드했다.
4. 재다운로드한 파일이 후보와 바이트 단위로 일치했다.
5. 사용자가 태블릿에서 문구 표시를 확인하고 새 필기를 추가한 후 동기화했다고 응답했다.
6. 회수한 파일에서 텍스트 객체가 그대로 보존되고 필기 객체 42개가 존재했다. 이미지로 필기를 확인했다.

이 실험은 **기존 문서 직접 쓰기와 태블릿 왕복**을 검증한다. 정확한 기기 앱 버전은 아직 확인하지 못했다.

## Drive 반영 확인, 태블릿 확인 대기

- 테스트 전용 가상 폴더 생성 및 테스트 노트 이동. 다른 도서관 항목은 의미가 동일함을 비교했다. 업로드 후 목록 파일 재다운로드가 일치했다.
- 테스트 노트에 표준 PDF 두 번째 페이지와 텍스트 객체 삽입. 기존 첫 페이지 객체 전체가 동일함을 확인했다. 업로드 후 재다운로드가 일치했다.

두 항목 모두 사용자 태블릿 화면 확인 전이므로 화면까지 검증됐다고 표시하지 않는다.

## 미검증/미완료

- 신규 문서 무인 등록·복제. 현재 일반 Drive 연결로 앱 전용 신규 등록을 수행할 수 없다.
- 실제 기기에서 휴지통·복원, 페이지/객체 삭제, 문서 이름 변경. 이 항목들은 합성 자료 테스트만 수행했다.
- iOS, 전체 이미지/도형/마스킹/회전 렌더, 음성 녹음 편집, 영구 삭제.
- Windows/Linux 실제 실행. CI 행렬은 추가했지만 로컬에서 실행한 것으로 주장하지 않는다.
- 설치 후 새 Codex 채팅에서 실제 스킬이 선택되는 사용성 검증.
- API의 원자적 조건부 쓰기. 커넥터에 해당 파라미터가 없어 지원하지 않는다.

요구사항의 '모든 기능 지원'과 '완전 자동 신규 문서 생성'은 아직 충족되지 않았다. 로컬 테스트 통과나 플러그인 설치를 이 요구사항의 완료로 취급하지 않는다.
