# 검증 기록

2026-09-28, macOS arm64에서 수행했다. 개인정보가 없는 요약만 저장한다.

## 통과

- Python 3.12.14 새 가상환경에 지정된 의존성 설치 후 `doctor` 실행.
- 합성 자료를 사용하는 자동 테스트 **49개** 통과.
- ZIP 경로 탈출/중복 콘텐츠, 비정상 필기 데이터, 압축 목록 크기·끝 검사.
- 편집 도중 오류가 발생했을 때 입력 불변, 오래된 해시 거절, 출력 파일 덮어쓰기 거절.
- 새 PDF/빈 페이지, 페이지 순서 변경/삭제, 객체 삭제, 문서·폴더 이동/휴지통/복원.
- 표준 PDF 가져오기 작업 명세와 실제 첨부 PDF 해시 매칭, 중첩 폴더 배치 계획.
- 사용자 테스트 전 일반 쓰기 거절, 원격/후보 변경 감지, 장치 왕복 기록에 추가 객체 요구.
- 미리보기와 유효한 PDF 내보내기. 근사 렌더를 `--strict`로 거절.
- 실제 비공개 `.flx` 샘플 **8개**에 텍스트 추가, 재직렬화/재읽기, 기존 필기 의미 보존. 샘플은 저장소에 넣지 않았다.
- 네이티브 ZIP에서 발견된 중복 `.itemInfo` 바이트 보존.
- 공식 `validate_plugin.py`, 두 스킬의 `quick_validate.py` 통과.
- Codex CLI를 통한 로컬 marketplace 등록 및 플러그인 설치. 설치 캐시에서 `capabilities` 실행 확인.
- PKCE state/만료 검사, 신뢰하지 않는 API·재개 주소 거절, 공개 APK 설정의 모호성 거절.
- 새 문서와 목록의 순차 등록, 고정 Drive ID 재시도, 중간 외부 변경 보존.
- 직접 연결의 문서·목록 동시 이름 변경, 휴지통/복원 순서, 중간 충돌 시 재개 기록.

## 실제 Android/Drive 실험

1. 사용자가 별도 테스트 노트를 생성했다.
2. 원본 바이트를 보관하고 UTF-8 텍스트 객체 하나를 넣었다.
3. 직전 원격 파일과 원본이 일치함을 확인한 뒤 같은 Drive ID에 업로드했다.
4. 재다운로드한 파일이 후보와 바이트 단위로 일치했다.
5. 사용자가 태블릿에서 문구 표시를 확인하고 새 필기를 추가한 후 동기화했다고 응답했다.
6. 회수한 파일에서 텍스트 객체가 그대로 보존되고 필기 객체 42개가 존재했다. 이미지로 필기를 확인했다.

이 실험은 **기존 문서 직접 쓰기와 태블릿 왕복**을 검증한다. 정확한 기기 앱 버전은 아직 확인하지 못했다.

## 신규 문서 자동 등록과 필기 왕복

1. APK에서 공개 OAuth 설정과 생성 요청 형식을 읽고, 파일·PDF·압축·전송 처리를 플러그인으로 구현했다.
2. 사용자가 시스템 브라우저에서 Google 로그인·동의를 완료했다. Mac의 로컬 콜백 수신기로 인증 코드를 받고 PKCE로 교환했다.
3. 새 연결에서 Flexcil 동기화 폴더와 목록의 앱 전용 속성을 실제로 읽었다.
4. 다른 스킬에서 전달할 수 있는 표준 PDF로 새 문서 UUID·목록 항목 UUID를 만들었다. 기존 테스트 노트와 별개의 새 Drive ID를 예약했다.
5. 가상 폴더에 배치하고 새 문서 등록·목록 갱신 후 두 파일을 재다운로드해 원본 후보와 비교했다.
6. 사용자가 태블릿에 새 문서와 PDF가 보인다고 확인하고 필기를 추가했다.
7. 필기 객체 **6개**를 회수했다. 문서/페이지 UUID, PDF 원본, 목록 참조가 유지됐고 렌더 이미지로 필기를 확인했다.

이 경로에는 Flexcil 데스크톱 앱, 태블릿 디버깅, 태블릿 보조 앱을 사용하지 않았다.
과거 공식 Mac 앱 UI로 노트를 만들었던 별도 기록과 구분되는 플러그인 직접 생성 시험이다.
초기 두 번의 조회에서는 필기가 없었으며 이를 성공 처리하지 않았다. 사용자가 실제로 필기한 뒤 회수에 성공했다.

## Drive 반영 확인, 태블릿 확인 대기

- 테스트 전용 가상 폴더 생성 및 테스트 노트 이동. 다른 도서관 항목은 의미가 동일함을 비교했다. 업로드 후 목록 파일 재다운로드가 일치했다.
- 테스트 노트에 표준 PDF 두 번째 페이지와 텍스트 객체 삽입. 기존 첫 페이지 객체 전체가 동일함을 확인했다. 업로드 후 재다운로드가 일치했다.
- PDF 암호 맵에 파일명을 넣던 오류를 수정했다. 테스트 PDF의 정확한 바이트로 대상을 식별해 암호 없는 PDF의 값을 빈 문자열로 바꾸었다. 메타데이터 외 17개 ZIP 항목과 기존 객체 44개를 보존했고 재다운로드가 일치했다.

두 항목 모두 사용자 태블릿 화면 확인 전이므로 화면까지 검증됐다고 표시하지 않는다.

## 미검증/미완료

- 기존 문서 전체 복제와 네이티브 노트 표지·템플릿 생성. 새 PDF 문서 자동 등록은 위에서 별도로 실증했다.
- 실제 기기에서 휴지통·복원, 페이지/객체 삭제, 문서 이름 변경. 이 항목들은 합성 자료 테스트만 수행했다.
- iOS, 전체 이미지/도형/마스킹/회전 렌더, 음성 녹음 편집, 영구 삭제.
- Windows/Linux 실제 실행. CI 행렬은 추가했지만 로컬에서 실행한 것으로 주장하지 않는다.
- 설치 후 새 Codex 채팅에서 실제 스킬이 선택되는 사용성 검증.
- API의 원자적 조건부 쓰기. 커넥터에 해당 파라미터가 없어 지원하지 않는다.

## 직접 연결의 도서관 작업 실증

새로 생성한 테스트 문서를 대상으로 이름 변경 → 루트 이동 → 휴지통 → 원래 폴더 복원 → 원래 이름 복구를 수행했다. 각 단계의 원격 원본 비교, 업로드, 재다운로드가 통과했다. 마지막에 필기 6개와 PDF 바이트, 문서/페이지 식별자, 다른 도서관 항목 및 기존 휴지통 내용이 보존됨을 비교했다. 단계별 태블릿 UI를 확인한 시험은 아니므로 Drive 검증으로 분류한다.

새 PDF 문서 자동 생성·폴더 배치·태블릿 왕복은 충족했다. '모든 Flexcil 기능 지원'은 위의 미완료 항목 때문에 아직 충족하지 않았다. 로컬 테스트나 설치를 전체 요구사항의 완료로 취급하지 않는다.
