# 개인정보와 복구

## 저장 위치

공개 배포물은 코드·스킬·문서·합성 테스트만 포함한다. Google Drive 연결 식별자는 서비스 종류를 지정하는 공통 connector ID이며 사용자 계정/토큰이 아니다.

개인 상태에는 라이브러리 ID, 플랫폼, 검증 상태와 변경 작업이 저장된다. 변경 작업에는 민감한 내용이 포함될 수 있는 원본 `.flx`, 후보 `.flx`, 계획과 결과가 있다. 로컬 상태 디렉터리는 POSIX에서 0700, 파일은 0600으로 생성한다. Windows에서는 사용자 디렉터리의 ACL을 따른다. 별도의 자체 암호화는 제공하지 않는다.

직접 연결에는 공개 클라이언트 설정, 임시 PKCE 상태, Google 토큰, 이어 올리기 세션 주소도 저장된다. 모두 설치 폴더 밖 `connections/` 또는 `operations/`에 저장하며 CLI 결과에 토큰을 반환하지 않는다. APK 설정 탐색은 ZIP/DEX의 공개 문자열만 읽고 실행하지 않는다.

자동 원격 로그·분석 전송은 없다. 포맷 엔진은 로컬에서 실행된다. 명시적 직접 연결 명령은 Google HTTPS 인증/Drive API를 호출한다. 기존 파일은 연결된 Codex Google Drive 앱으로도 전송할 수 있다. 설치 시 선택한 패키지 저장소에서 Python 의존성을 받는다.

저장소나 공유 문서에 백업·설정·커넥터 응답을 복사하지 않는다. 잠시 쓰는 다운로드 URL도 로그나 README에 넣지 않는다. 버그 보고에는 합성 재현 자료와 에러 코드만 포함한다.

## 복구

문서 작업은 source/candidate/receipt를 남긴다. `preflight`는 최신 파일의 해시를 원본과 비교한다. 후보가 이미 서버에 있으면 재업로드를 생략한다. `verify`는 다시 내려받은 파일을 비교한다.

`rollback`은 서버가 여전히 그 후보인 경우에만 복원 파일을 만든다. 이것은 업로드 명령이 아니다. 이후 편집이 있으면 기존 백업을 강제로 덮어쓰지 않고 별도 변경 계획을 만든다.

목록/휴지통 작업은 각 파일의 source/candidate를 따로 보존한다. 중단된 작업은 각 파일의 해시를 대조해서 완료된 단계를 판정한다. 두 파일 쓰기는 원자적이지 않다. 복구 중 생긴 중복 참조를 '사용하지 않는 문서'로 오인해 삭제하지 않는다.

새 문서는 Drive ID를 예약한 뒤 문서와 목록을 순서대로 작성한다. `publish-document`는 동일 작업 ID로 재개하고, `publish-update`는 이미 적용된 후보를 건너뛴다. 중간 충돌로 등록된 문서나 수정된 제목이 남을 수 있으므로 작업 기록의 완료 단계와 최신 원격 내용을 먼저 확인한다. 새 작업을 무작정 생성해 중복 등록하지 않는다.

오래된 백업은 자동으로 지우지 않는다. 필요가 없어진 작업 디렉터리는 사용자가 보관 기간을 결정한 뒤 삭제한다. 개인 상태 디렉터리를 지우면 프로필과 복구 자료가 함께 사라진다.
